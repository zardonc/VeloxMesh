<objective>
Make client cancellation and output failure first-class terminal inputs. The handler must stop forwarding when the client is gone, cancel upstream work, and never manufacture a second terminal event from a bare channel close.

Deliverable: checked SSE write helpers, derived-context cancellation propagation, a precise terminal-output contract, and handler/service tests for disconnect and duplicate-DONE prevention.
</objective>

**Duration:** 1 engineer-day. No browser test, real HTTP proxy, deployment, or provider credential is required.

**Test environment:** Local `httptest` handler tests using a fail-on-Nth-write `ResponseWriter`, flush spy, deterministic stream channel, and a gateway fake that observes context cancellation.

<acceptance_criteria>
1. Chat streaming creates a derived cancellable context and passes it to gateway execution.
2. Any SSE write error cancels upstream work and ends forwarding without a later write.
3. Successful completed/provider-error sequences contain no more than one `[DONE]`; a bare close does not add one.
4. Client cancellation and write failure do not generate terminal bytes after the failure/disconnect.
5. Existing headers and valid successful OpenAI-compatible stream bytes remain compatible.
</acceptance_criteria>

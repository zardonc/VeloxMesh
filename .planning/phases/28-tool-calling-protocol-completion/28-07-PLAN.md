<failure_modes>
1. A tool request reaches semantic-cache lookup or store and returns a response produced for a different tool schema, choice, call history, or result.
2. A response-rule-enabled stream buffers, rewrites, drops, or delays the first tool-call identity fragment or its argument bytes.
3. Fusion performs member or judge admission/provider I/O before rejecting a request containing tools, tool calls, or tool results.
4. A pre-visible provider error falls through to an incompatible candidate, or a post-visible tool error switches provider and duplicates visible output.
5. Malformed provider events, invalid final arguments, finish-reason conflicts, cancellation, client write failure, or channel close bypass the existing terminal finalizer.
6. Duplicate terminal paths settle Usage, release admission, record health/breaker state, emit terminal metrics, or close traces more than once.
7. Logs, traces, metric labels, or error text expose prompts, schemas, arguments, results, call IDs, indexes, or tenant-defined tool names, or create a per-fragment high-cardinality series.
8. Protocol state is retained beyond the request, grows with total stream bytes, or introduces external I/O per fragment.
9. A no-tools request changes cache, response-rule, fallback, SSE, terminal, or Usage behavior while the tool path is being integrated.
10. Current official provider documentation or pinned SDK behavior contradicts the locked contract and implementation proceeds without revising the plan.
</failure_modes>

<threat_model standard="OWASP ASVS L1">
High-risk findings block the phase gate. The relevant ASVS L1 controls are boundary validation and encoding (V5), error handling and logging (V7), and API/web-service behavior (V13), with indirect access-control protection through capability and provider preflight (V4).

- **H1 Protocol confusion / data disclosure:** cache and response rules must not reinterpret tool payloads. Block if any tool-protocol request is read from or written to semantic cache, or if rules inspect/rewrite arguments or results.
- **H2 Provider or identity substitution:** Fusion and incompatible fallback must fail before I/O; post-visible failures must not switch provider. Block on any member/judge call or fallback after a visible tool event.
- **H3 Terminal/accounting corruption:** all completion, error, cancel, and write-failure paths must enter the Phase 27 finalizer once. Block on duplicate Usage settlement, missing release, duplicate terminal emission, or provider-health damage from policy/client errors.
- **H4 Sensitive/high-cardinality telemetry:** block raw payloads, call identifiers, tool names, prompts, or per-fragment labels in logs, metrics, traces, and client errors.
- **H5 Resource exhaustion:** block whole-stream buffering or unbounded state for protocol traffic, new per-fragment network I/O, or state that grows beyond validated unfinished-call count and existing request limits.

The final summary must list each H1-H5 test or static assertion and mark the gate failed if any high-risk item lacks both a pre-edit failing behavior and a post-edit passing result.
</threat_model>

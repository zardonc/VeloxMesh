## 先列失败方式

embedding 短期 memo 必须默认关闭、容量和 TTL 有界。相同文字不同账户/scope/目标模型不能复用；不同 embedding 服务实例和输入前缀不能共用状态。返回向量必须复制，调用者修改不污染以后请求；到期/淘汰/失败/取消不能返回过期或错误向量。冷态并发允许分别调用真实 embedding，不引入共享取消或无限等待。只缓存成功且维度/数值合法的向量，不缓存答案，不新增主模型调用，不改变缓存读取截止。未知文本仍走真实 embedding，不能把重复问题收益套用到独立低命中负载。

输入前缀仅显式配置，不根据模型名字自动猜测。前缀变化进入 cache scope 的表示版本，不能命中旧表示；空前缀保留既有 scope 兼容性。非法/过长前缀及非法 memo 配置必须拒绝。模型服务的实际自动前缀、加载/排队/推理日志仍是证据缺口。

## 开发与验证顺序

1. 新鲜实际组件和本地模型 preflight；先保存新增真实失败用例，再修改产品实现。
2. 增加默认关闭的 embedding memo 与显式输入前缀，记录 memo hit/miss、有效表示；先局部真实验证隔离、复制、TTL、容量、断连恢复及计费。
3. 使用与旧 150 问集合不同的固定多 FAQ 问法。预先固定 raw/.92 和 search_query/.84 两种候选，不按留出分数继续调参；正例与跨答案/否定/数值陷阱分别统计。留出集零误命中优先，不承诺示例 70% 已获业务批准。任何误命中保持 profile 未发布。
4. 最终候选运行实际 direct/off/low-hit/miss/hit/bypass、embedding 压力及适用协议回归。稳定窗口 8 RPS、100 请求、C4 上限、至少六组平衡顺序；单测 Go 与外层各 60 秒硬截止，保存实际并发、发送滞后和全部失败。
5. 分场景报告：普通请求 application residual P95≤10ms/P99≤15ms；cache read P95≤100ms同时报告超时；warm hit 完整 P95≤60ms 且≤matched off/2，usage=0；低命中原 1.05 与候选 1.25 或 off+40ms 均报告。C8 饱和只报告容量/长尾，不能套普通请求门槛改判通过。候选预算不替代正式发布合同；开放问题未解决不合并 main。

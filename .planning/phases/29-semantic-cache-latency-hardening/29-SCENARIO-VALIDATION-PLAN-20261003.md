# Phase 29：按场景评测及补充验证计划

依据：引用任务「分析 Phase 29 遗留问题」及当前 `a35592c3` 的代码/修复复测证据。本文在新增测试执行前制定。本轮使用实际应用、真实 SQLite/Redis/Qdrant/模型服务；故障只由透明网络转发器延迟或断开真实连接产生，不生成 embedding、聊天或存储响应。

## 评测标准

以下是本轮诊断预算，适用于明确记录的模型、输入及负载；不代表已批准的生产 SLO。原 D-08 低命中完整响应 1.05 倍门槛继续独立显示，不能用新诊断指标覆盖旧失败。不同聊天/embedding 模型、命中/miss/故障/饱和窗口不混合计算 P95。

| 场景 | 本轮评测方法与预算 |
|---|---|
| cache-off / 不符合缓存条件的请求 | 真实响应及结算正确；每请求网关处理 = handler − 主模型调用，P95≤10ms、P99≤15ms。Provider 自身耗时单独列出；不把不同模型的完整响应 P95 混在一起 |
| 正常 eligible miss | 扣除主模型调用和 cache_read 的网关处理 P95≤10ms、P99≤15ms；缓存本地剩余处理 = cache_read − 前台 embedding 阶段 − vector_search，P95≤2ms；读取 P95≤100ms预算+5ms调度容差。正常完成 Lookup 的向量只计算一次；异步 Store 无重复 embedding |
| 已预热的 cache hit | ≥99%命中、答案与种子一致、零新增计费；完整响应 P95≤min(110ms, 同聊天模型 cache-off P95×0.5)。报告 embedding 延迟，避免把外部服务等待误认为网关 CPU 时间 |
| embedding 单独及并行压力 | 探测预期维度，所有向量匹配维度、非零且有限；C4 的 P95≤100ms 为当前读预算的适配性诊断，单调用2秒硬截止。C8结果标为服务容量，不外推网关并发能力 |
| 读取超时、依赖连接中断 | 主请求真实转发且结算一次，读取工作/队列有界，恢复后可写入及命中。故障完整响应与正常响应分别统计，不套用1.05倍 |
| 饱和/突发 | 强制实际并发4/8，报告主响应成功率、实际并发、吞吐、缓存许可拒绝、队列丢弃、恢复。调度积压的开放到达负载标记为未维持目标RPS；不能据此判定网关性能失败或通过 |

10/15ms 网关预算用于区分此前约4.7ms正常处理与>15ms尖峰；2ms缓存本地预算针对此前约0.119ms剩余处理保留余量。warm-hit 相对预算验证实际缓存收益。生产 SLO 仍需业务负载目标及服务承诺。

## 执行顺序

1. 确认组件 readiness、聊天模型可用性，以及本地两款 embedding 的真实调用；第二款为当前 `/v1/models` 中提供的 `text-embedding-nomic-embed-text-v1.5`。预热/冷启动单独记录，不混入稳定 P95。
2. 扩展维度断言、body-read 错误文本及测试开关；添加真实 warm-hit、缓存 bypass、强制并发、双 embedding 模型同账户/同数据库切换、透明网络延迟/断开恢复和跨进程 Qdrant 创建用例。
3. 对同一输入比较 embedding 本机直连和 VM/SSH 路径，分别测单独及与聊天模型同时运行；不能从客户端计时推断纯推理时间。没有服务端队列/GPU日志时明确保留归因边界。
4. 使用4/8/12/16 RPS、每窗口100个，测off/on；另做真实C4/C8突发以覆盖实际并发，而不是只设置上限。稳定比较计划至少6组，每组100个direct、100个off、100个on；如环境出现错误，保留失败并按实际可用证据调整后续负载，不删除样本。
5. 对两款 embedding 做完整网关生命周期及同数据库隔离；以现有测试 FAQ 的事实构造明确标注的扩展诊断集，检查同义命中和不同答案误命中。这个集合不能代替未经提供的生产业务验收集。
6. SANS 小批次同完整请求 direct/off/on 对照；每次最多3个完整请求，统一12秒截止，每项后端测试硬截止60秒。失败时关联HTTP网络分段、取消、结算，并保留上游网络与内部处理未区分的情况。
7. 独立观测器开/关及 profiling；保存 Go trace 与可取得的 VM CPU/steal 证据。尖峰未出现时保留旧根因未确认的结论。

每项后端测试保留60秒硬截止；每次退出停止自行启动的隔离容器与连接代理，关闭SSH转发。密钥只从未入库环境读取，经stdin传递；原始失败、计划、校验值及统计脚本一并保留。

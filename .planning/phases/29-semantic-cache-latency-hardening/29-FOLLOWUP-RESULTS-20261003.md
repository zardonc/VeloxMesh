# Phase 29 后续修正与真实复测

日期：2026-10-03（Vancouver；原始日志 UTC 为 10-04）。基线 HEAD `f19f316`。新改动保留在工作区供审查；未合并 main，未启用生产缓存或改生产阈值。复现入口和原始证据：[followup-20261003](measurements/followup-20261003/)。

## 结论

新增默认关闭的有界 embedding 向量复用，以及显式输入前缀和表示版本隔离。真实边界/断连/计费/配置验证通过；相同问题命中 P95 从 **36.511ms 降到 6.444ms**，100 次命中期间不再调用 embedding，只有一个种子请求计费。

普通负载应用处理 P95 **4.981–5.665ms**、P99 **5.814–7.832ms**，通过本轮分场景诊断预算。低命中完整响应仍未达到原 `1.05×off`；候选 `1.25×off 或 off+40ms` 通过。不能声称 memo 改善了低命中 P95：本轮 memo 的 P95 更高，差值置信区间跨零。

独立留出集否定了旧已见集合上的乐观校准：Nomic `search_query: ` / .84 出现 **3/20 不安全负例命中**，只召回 4/12 正例。原 .92 在两模型均是 0/12 正例、0/20 负例。候选不得发布；原门槛、业务召回目标与资源/冷态证据仍待处理，不满足原全通过合并条件。

OpenRouter、Gemini、SANS 按用户授权的资源/429 排除处理，**SKIP，不计 PASS**。本轮只对健康 GPT 执行少量协议和事实验证，负载集中于真实本地模型；没有 mock Provider、模型回复或存储。

OpenRouter 的已有直接HTTP429未保留原始错误正文，具体额度类型/周期未确认；本轮按资源排除处理，不将未知429原因写成已确诊的每日额度耗尽。

## 性能对照：实际场景分别评价

六组顺序平衡，每条件每组 100，间隔125ms、目标8RPS、C4上限，共 **2,400 正式请求全部成功**。实际峰值并发：direct/off/memo 为2，普通 cache on 为3；这不是“饱和 C4”测试。各组先保存 warmup，正式样本不混入 warmup。请求 ID 将 HTTP、上游/embedding HTTP、cache、向量、仓库、健康和结算分段关联。

`application residual = 同请求 http_handler − provider_complete − cache_read`，含认证、路由、SQL/Redis等，不是纯 CPU。只按同请求相减，不把不同阶段 P95 相加减作因果结论。

| 稳定场景 | n | hit | 完整 P95/P99 ms | application P95/P99 ms |
| --- | ---: | ---: | ---: | ---: |
| direct | 600 | 0 | 125.649 / 196.993 | 不经过网关 |
| cache off | 600 | 0 | 130.145 / 197.072 | 5.665 / 7.533 |
| cache on、memo off | 600 | 24 | 148.366 / 188.909 | 5.221 / 7.832 |
| cache on、memo on | 600 | 24 | 154.829 / 214.548 | 4.981 / 5.814 |

普通 cache read P95/P99 为22.944/26.309ms，memo 为23.522/29.451ms；对应 lookup embedding 为21.531/24.637 和21.728/26.964ms。1,200 次正式缓存读取无 timeout/concurrency_full。每个 memo 窗口 embedding HTTP **97次**、非memo **101次**（含一次 warmup）；减少的是4次重复输入，不是所有96次新问题 miss 的计算。

| 场景/指标 | 本轮诊断标准 | 结果 |
| --- | --- | --- |
| 普通 application | P95≤10ms，P99≤15ms | off/on/memo 均通过 |
| 缓存读取 | P95≤100ms，同时检查 timeout/命中/质量 | 延迟及无超时通过；语义召回质量未通过，不能仅看截止判通过 |

## 本地模型和网络/资源证据

实际模型元数据：Qwen Q8_0、collection `nomic-bert-moe` Q8_0、Nomic `nomic-bert` Q4_K_M。两款embedding均实际返回768维；Nomic由未加载变为加载状态，本轮没有人为卸载、替换权重或更改服务配置。

VM embedding 压力：实际 C4、100正式样本全部成功，P95/P99 42.511/44.203ms。16次首次并发预热均成功，但最长203.996ms；这是已加载服务的首次并发窗口，不是真实卸载后的冷启动。100ms网关读取截止在该窗口可能触发旁路；暖态结果不能覆盖冷态行为。

主机直接 `127.0.0.1:1234`、绕过网关和SSH：单独embedding100次；随后embedding/chat各100次独立到达计划，均8RPS、各C4上限。300正式请求全成功，保留 Windows 发送滞后（P95约14ms）：

| 直连场景 | P95 / P99 ms |
| --- | ---: |
| embedding 独立 | 56.916 / 59.074 |
| embedding 与chat并行 | 35.435 / 101.456 |
| 同窗口chat | 149.360 / 280.806 |

混合窗口embedding有长尾，但P95比独立窗口更低，不能据此宣称“资源竞争增加固定Xms”。两窗顺序不同、Go/Node客户端和热状态也不同，不能与VM分段作逐项相减定位SSH延迟。已有上一轮同Go客户端匹配实验约1ms差异保留为历史证据。当前新证据证明：无网关/SSH也有模型尾部波动；尚不能量化GPU/CPU竞争对embedding的贡献。

补查实际 LM Studio 后端日志，保存去除请求/回复正文的[backend-timing.json](measurements/followup-20261003/backend-timing.json)：C8时段193个可解析任务，观测到slot0–3、最多4个同时活跃；prompt P95 31.86ms、decode245.07ms、total271.19ms。混合直连时段100任务，total P95 123.98ms。这支持本地主模型生成和服务内调度是饱和长尾的重要来源，不能把前端API并发上限等同于实际推理并行度；不据此断言配置固定上限为4。日志只有秒级wall-time，未与gateway ID配对，也未提供embedding推理/排队时间，不能从HTTP P95减后端P95得到精确排队耗时。

## 独立语义留出集与功能正确性

32个固定新问法：3类FAQ，12同答案、20不可安全复用的问法；没有旧问题加后缀，也未根据分数选取。候选在测试前固定，未按留出集调整阈值。真实App HTTP→cache→embedding→Qdrant→SQLite；种子来自真实Qwen响应，错误命中按种子hash/期望答案身份判断，miss真实调用主模型、结算。

| 候选 | 正例召回 | 不安全负例命中 | 决策 |
| --- | ---: | ---: | --- |
| collection / raw / .92 | 0/12 | 0/20 | 安全性观察通过，召回不足 |
| Nomic / raw / .92 | 0/12 | 0/20 | 同上；一个初始seed读取超时，正式正例无读取超时 |
| Nomic / search_query / .84 | 4/12 | 3/20 | 拒绝，不能发布 |

误命中分别是“第八天能否退款”“试用是否恰好七天”“退款是否可十四天”；一般政策答复被复用到了不同答案/数值判断。该证据解释了为什么已见150问上的0误命中不足以推荐降阈值。此留出集小，0/20也不能证明真实误命中率≤1%；70%召回仅是报告示例，不是批准的业务目标。

此处验证缓存匹配身份，不宣称0.5B主模型业务事实准确。健康GPT分别实际通过3个直接事实、网关事实/精确缓存/结算，以及10个协议用例：SSE一次终止/结算、取消、buffered、Fusion、required/named/auto/omitted/none和流式工具续接。另有认证、单次embedding复用、实际网络截止、跨进程冷集合、Qdrant错误分类、pending不可见安全回归全部通过。

## 发布判定与证据完整性

普通处理、精确命中性能和实施边界可按本轮**诊断预算通过**。仍开放：原1.05低命中门槛；独立语义召回/数值否定安全策略；真实冷态、服务内部embedding计时与模型版本/自动前缀；饱和SLO及少数自然尖峰。429历史失败按授权暂时排除，不要求本轮重复耗额度，但未解释的历史非429体生成超时保留后续追踪。

不把不同场景P95混用，不以降低截止导致零命中冒充性能通过，不采纳speculative主模型调用，不把所有VM组件“无失败”写成无限处理能力。正式SLO/业务策略未闭环，**未合并main**。

原始失败和误配置窗口完整保留：`red-memo`为修复前回归，缺失测试名为执行器问题，`stable-1..3`的memo未开启、后续中断调度不参与优化结果；正式使用`verified-stable-1..6`。三种quality条件单独列出，0召回用例的“HTTP/安全性PASS”不等于质量PASS。

`go build ./...`、`go vet -tags phase29preflight ./...`、既有cache/config/gateway包回归和diff检查通过。包回归Go和外层各60秒截止，真实VM单例同样限制60秒。没有新增mock单元用例。配置负例和整链路产物可重放；`manifest.json`保存源码/二进制/日志SHA及筛选规则，`verified-build-source.json`对应正式性能二进制构建后的源码快照，后加配置边界用例单独编译。

最后runner实际检查Redis/Qdrant/PostgreSQL全部停止，SSH连接关闭；本地主机实验只使用用户现有模型服务，无额外服务进程。凭据审计通过。原始日志保留Qdrant版本/首启readiness告警，不把告警隐藏为无问题；readiness最终成功，测试才开始。
